    Μάθημα 7: Εφαρμογή με μενού¶

    Python και MySQL: μια πλήρης εφαρμογή με μενού, χτισμένη από συναρτήσεις, που εμφανίζει, ψάχνει, προσθέτει, αλλάζει και σβήνει δεδομένα
    Διάρκεια: 2 κύκλοι × περίπου 45′ εργασία (2 διδακτικές ώρες)

    Φύλλο εργασίας

    Αυτή η σελίδα εξηγεί τις έννοιες. Οι ασκήσεις και οι οδηγίες για κάθε κύκλο βρίσκονται στο Φύλλο εργασίας 7. Δούλεψε με τις δύο σελίδες ανοιχτές.

    Αρχεία εργαστηρίου¶

    Αρχείο Κύκλος
    01-start-state.sql πριν αρχίσεις
    02-menu.py 1
    03-read.py 1
    04-write.py 2
    05-final.py 2

    Η αποστολή¶

    Μέχρι τώρα κάθε πρόγραμμά σου έκανε ένα πράγμα και τελείωνε. Μια πραγματική εφαρμογή δεν λειτουργεί έτσι: δείχνει ένα μενού, περιμένει να διαλέξεις, κάνει τη δουλειά, και ξαναρωτά, ώσπου να της πεις να βγει.

    Σήμερα φτιάχνεις μια τέτοια εφαρμογή για τη βιβλιοθήκη παιχνιδιών. Δεν μαθαίνεις νέα SQL: όλα όσα ξέρεις (SELECT, INSERT, UPDATE, DELETE, παράμετροι, commit, rowcount, επιβεβαίωση) μπαίνουν σε ένα πρόγραμμα. Αυτό που μαθαίνεις είναι πώς οργανώνεται ένα μεγάλο πρόγραμμα: σε μικρές συναρτήσεις, που η καθεμία κάνει μία δουλειά, και ένα κύριο πρόγραμμα που τις καλεί. Χωρίς αυτήν την οργάνωση, ο ίδιος κώδικας θα ήταν ένα κομμάτι 170 γραμμών, αδύνατο να το διαβάσεις ή να το αλλάξεις.

    Στο τέλος θα μπορείς¶

    • να γράφεις συναρτήσεις με παραμέτρους που κάνουν μία δουλειά, και να τις καλείς.
    • να χρησιμοποιείς το return για να επιστρέψει μια συνάρτηση τιμή, και να εξηγείς τι είναι το None.
    • να εξηγείς γιατί οι μεταβλητές μέσα σε μια συνάρτηση δεν φαίνονται έξω από αυτήν.
    • να γράφεις μενού με while True, if/elif/else και break.
    • να περνάς τη σύνδεση στις συναρτήσεις ως παράμετρο και να ξαναχρησιμοποιείς κώδικα (π.χ. την print_games).
    • να βγαίνεις νωρίς από μια συνάρτηση με return.
    • να προσθέτεις μια νέα επιλογή στο μενού χωρίς να χαλάς τις υπόλοιπες, και να δοκιμάζεις την εφαρμογή με σχέδιο δοκιμών.

    Κύκλος 1 — Το μενού και οι συναρτήσεις¶

    Σε αυτόν τον κύκλο μαθαίνεις τα εργαλεία οργάνωσης (συναρτήσεις, return, μενού) και φτιάχνεις τον σκελετό της εφαρμογής, με τις δύο πρώτες επιλογές να δουλεύουν.

    1.1 Γιατί συναρτήσεις¶

    Τη συνάρτηση show του Μαθήματος 4 τη θυμάσαι: έχει όνομα, παραμέτρους και ένα σώμα που κάνει μία δουλειά, και την καλείς όσες φορές θέλεις. Η εφαρμογή μας έχει πέντε ενέργειες (εμφάνιση, αναζήτηση, προσθήκη, αλλαγή τιμής, διαγραφή) και μερικές βοηθητικές δουλειές. Κάθε δουλειά γίνεται μία συνάρτηση:

    def print_games(rows):
    """Εμφανίζει σε στήλες τα παιχνίδια της λίστας rows."""
    for game_id, title, genre, year, price in rows:
        print(f"{game_id:>3}  {title:<20} ...")

    Τρία οφέλη:

    • Μικρά κομμάτια. Κάθε συνάρτηση χωρά στην οθόνη και δοκιμάζεται μόνη της.
    • Επαναχρησιμοποίηση. Η print_games θα εμφανίζει το αποτέλεσμα και της εμφάνισης και της αναζήτησης: την έγραψες μία φορά.
    • Ευανάγνωστο κύριο πρόγραμμα. Η main μοιάζει με πίνακα περιεχομένων: «αν η επιλογή είναι 1, εμφάνισε· αν είναι 2, ψάξε…».

    1.2 Η σύνδεση περνά ως παράμετρος¶

    Κάθε ενέργεια χρειάζεται τη σύνδεση με τη βάση. Δεν θα τη φτιάχνει η καθεμία (το άνοιγμα σύνδεσης είναι αργό), και δεν θα τη βάλουμε σε «καθολική» μεταβλητή. Την ανοίγουμε μία φορά στην main και την περνάμε στις συναρτήσεις ως παράμετρο:

    connection = connect()
list_games(connection)

    Κάθε συνάρτηση φτιάχνει τον δικό της κέρσορα, τον χρησιμοποιεί και τον κλείνει:

    def list_games(connection):
    cursor = connection.cursor()
    cursor.execute("SELECT ...")
    rows = cursor.fetchall()
    cursor.close()

    Ο κέρσορας είναι φτηνός. Η σύνδεση είναι το «ακριβό» αντικείμενο, και την κλείνει η main στο τέλος.

    Γιατί υπάρχει connection.commit() στην αρχή κάθε γύρου του μενού;

    Η σύνδεση μένει ανοιχτή όσο τρέχει η εφαρμογή. Από το πρώτο SELECT, η MySQL ξεκινά μια συναλλαγή και κρατά μια «φωτογραφία» των δεδομένων, ώσπου να γίνει commit ή rollback. Αν στο μεταξύ κάποιος άλλος αλλάξει κάτι (π.χ. εσύ από το phpMyAdmin), η εφαρμογή δεν το βλέπει. Το commit() στην αρχή κάθε γύρου τελειώνει την ανοιχτή συναλλαγή, και ο επόμενος γύρος ξεκινά με «νέα φωτογραφία». Δεν χάνεται τίποτα, γιατί οι αλλαγές της εφαρμογής γίνονται ήδη μόνιμες με το δικό τους commit. Στην Πρόκληση 3 θα το δεις με τα μάτια σου.

    1.3 return: η συνάρτηση επιστρέφει μια τιμή¶

    Μια συνάρτηση μπορεί να επιστρέψει μια τιμή στον κώδικα που την κάλεσε, με το return:

    def connect():
    return mysql.connector.connect(host="localhost", user="root", password="", database="game_library")

connection = connect()          # η τιμή που επέστρεψε η συνάρτηση μπαίνει στη μεταβλητή

    Μην μπερδεύεις το return με το print. Το print δείχνει κάτι στον άνθρωπο, στην οθόνη. Το return δίνει μια τιμή στο πρόγραμμα, ώστε να τη χρησιμοποιήσει παρακάτω. Μια συνάρτηση που δεν έχει return επιστρέφει αυτόματα None, την τιμή που σημαίνει «τίποτα». Οι list_games και show_menu δεν επιστρέφουν τίποτα, γιατί κάνουν τη δουλειά τους με print.

    1.4 Τοπικές μεταβλητές¶

    Οι μεταβλητές που φτιάχνεις μέσα σε μια συνάρτηση (π.χ. η rows της list_games) υπάρχουν μόνο όσο τρέχει η συνάρτηση. Μετά εξαφανίζονται, και ο υπόλοιπος κώδικας δεν τις βλέπει:

    list_games(connection)
print(rows)                     # NameError: name 'rows' is not defined

    Οι τιμές ταξιδεύουν με συγκεκριμένους τρόπους:

    Κατεύθυνση Πώς
    από έξω προς τη συνάρτηση παράμετροι (list_games(connection))
    από τη συνάρτηση προς τα έξω return (connection = connect())

    1.5 Το μενού: while True, if/elif/else, break¶

    Το μενού είναι ένας βρόχος που δεν τελειώνει από μόνος του:

    while True:                          # «για πάντα»
    show_menu()
    choice = input("Επιλογή: ")

    if choice == "1":
        list_games(connection)
    elif choice == "2":
        search_games(connection)
    elif choice == "0":
        break                        # βγαίνει από τον βρόχο
    else:
        print("Άγνωστη επιλογή.")
    • Το while True: επαναλαμβάνει για πάντα. Ο μόνος τρόπος να βγεις είναι το break, που σταματά τον βρόχο. Αν το ξεχάσεις, το πρόγραμμα δεν τελειώνει ποτέ (πάτα Ctrl + C).
    • Η choice είναι κείμενο (η input δίνει πάντα κείμενο), άρα τη συγκρίνεις με κείμενο: "1", με εισαγωγικά. Η choice == 1 δεν γίνεται ποτέ αληθής.
    • Στο if γράφεις == (σύγκριση). Το = είναι ανάθεση και δίνει σφάλμα.
    • Το else πιάνει όλα τα υπόλοιπα: έναν αριθμό που δεν είναι στο μενού, ένα γράμμα, ένα κενό Enter. Επειδή δεν μετατρέπουμε την επιλογή σε αριθμό, η εφαρμογή δεν σταματά όταν πληκτρολογήσεις κάτι παράξενο στο μενού.

    Κύκλος 2 — Αλλάζω δεδομένα και ολοκληρώνω¶

    Σε αυτόν τον κύκλο μπαίνουν στη συνάρτηση και οι αλλαγές, και η εφαρμογή ολοκληρώνεται. Δεν υπάρχει νέα SQL: υπάρχει νέα οργάνωση.

    2.1 Οι αλλαγές μέσα σε συναρτήσεις¶

    Η add_game και η change_price είναι ο κώδικας των Μαθημάτων 5 και 6, μέσα σε συναρτήσεις. Ακολουθούν το γνωστό μοτίβο: ρωτούν τον χρήστη, στέλνουν την εντολή με παραμέτρους, κάνουν commit και αναφέρουν το αποτέλεσμα (με lastrowid ή με rowcount). Ο κανόνας του Μαθήματος 5 ισχύει όπως πάντα: ό,τι δίνει ο χρήστης μπαίνει στη SQL μόνο ως παράμετρος.

    2.2 Συνάρτηση που επιστρέφει τιμή ή None¶

    Η find_title είναι μια συνάρτηση που επιστρέφει: ψάχνει ένα παιχνίδι με το id που της δίνεις και επιστρέφει τον τίτλο του. Αν δεν υπάρχει τέτοιο παιχνίδι, επιστρέφει None:

    title = find_title(connection, game_id)
if title is None:
    print("Δεν υπάρχει παιχνίδι με αυτό το id.")

    Η συνάρτηση έχει δύο return. Μόλις εκτελεστεί ένα return, η συνάρτηση τελειώνει εκείνη τη στιγμή και ο κώδικας που ακολουθεί δεν τρέχει. Η find_title δεν δείχνει τίποτα στην οθόνη: δίνει στον καλούντα τα στοιχεία και εκείνος αποφασίζει τι θα κάνει. Γι' αυτό μπορεί να τη χρησιμοποιήσει όποια συνάρτηση τη χρειαστεί.

    2.3 Πρόωρη έξοδος με return¶

    Στην delete_game έχουμε δύο περιπτώσεις που δεν πρέπει να συνεχίσουν: το id δεν υπάρχει, ή ο χρήστης δεν επιβεβαίωσε. Αντί να φωλιάσουμε όλο τον κώδικα μέσα σε if/else, ελέγχουμε το πρόβλημα, ενημερώνουμε και φεύγουμε με ένα return χωρίς τιμή:

    title = find_title(connection, game_id)
if title is None:
    print("Δεν υπάρχει παιχνίδι με αυτό το id.")
    return                                   # φεύγει από τη συνάρτηση

answer = input(f"Να σβηστεί το «{title}»; (ναι/όχι): ")
if answer != "ναι":
    print("Ακυρώθηκε. Δεν σβήστηκε τίποτα.")
    return                                   # φεύγει κι από εδώ

# ... εδώ φτάνει ο κώδικας μόνο όταν όλα είναι εντάξει: κάνει τη διαγραφή

    Το return χωρίς τιμή επιστρέφει None και απλώς τερματίζει τη συνάρτηση. Ο κώδικας που μένει στο τέλος είναι ο «κανονικός δρόμος», χωρίς βαθιά εσοχή. Η επιβεβαίωση και ο έλεγχος του rowcount με rollback είναι τα δίχτυα ασφαλείας του Μαθήματος 6.

    2.5 Δοκιμάζω την εφαρμογή¶

    Ένα πρόγραμμα που «φαίνεται να δουλεύει» δεν είναι δοκιμασμένο. Μια δοκιμή έχει σχέδιο: μια σειρά ενεργειών, τι περιμένεις να συμβεί σε κάθε βήμα και τι συνέβη πραγματικά. Στο φύλλο εργασίας θα γράψεις ένα τέτοιο σχέδιο και θα το εκτελέσεις. Θα δοκιμάσεις και τα όριά της: τι γίνεται αν δώσεις γράμματα στη χρονιά, και ποιο από τα δεδομένα σου επηρεάζεται.

    Για να θυμάσαι¶

    • Μια συνάρτηση κάνει μία δουλειά. Την ορίζεις με def, της δίνεις τιμές με παραμέτρους και παίρνεις τιμή πίσω με return.
    • Χωρίς return, μια συνάρτηση επιστρέφει None. Το return τερματίζει αμέσως τη συνάρτηση.
    • Οι μεταβλητές μέσα σε συνάρτηση είναι τοπικές. Προς τα μέσα τις περνάς με παραμέτρους, προς τα έξω με return.
    • Τη σύνδεση την ανοίγεις μία φορά και την περνάς ως παράμετρο. Κάθε συνάρτηση φτιάχνει και κλείνει τον δικό της κέρσορα.
    • Το μενού: while True: + if/elif/else + break στην επιλογή εξόδου. Η επιλογή είναι κείμενο.
    • Μια ανοιχτή συναλλαγή κρατά «φωτογραφία» των δεδομένων. Σε μια εφαρμογή που μένει ανοιχτή, το commit() στην αρχή κάθε γύρου φέρνει τα τελευταία δεδομένα.
    • Ό,τι έρχεται από τον χρήστη μπαίνει στη SQL μόνο ως παράμετρος.
    • Η εμφάνιση και η ανάκτηση δεδομένων είναι ξεχωριστές δουλειές: ξεχωριστές συναρτήσεις.
    • Δοκιμάζεις με σχέδιο: ενέργειες, αναμενόμενο αποτέλεσμα, πραγματικό αποτέλεσμα.
