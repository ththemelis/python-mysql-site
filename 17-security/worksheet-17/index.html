    Φύλλο εργασίας — Μάθημα 17: Ασφάλεια: λογαριασμοί, δικαιώματα και SQL injection¶

    Πώς δουλεύουμε

    Η θεωρία είναι στη σελίδα Μάθημα 17. Εδώ είναι οι ασκήσεις. Στις ασκήσεις πρόβλεψης γράψε πρώτα την απάντησή σου και μετά τρέξε την εντολή. Μια λάθος πρόβλεψη είναι χρήσιμη: δείχνει τι δεν έχει ακόμη γίνει σαφές. Σήμερα πρόβλεψε ποιο σφάλμα θα δώσει η βάση και τι θα κάνει το πρόγραμμα με μια «περίεργη» είσοδο.

    Κύκλος Εργασία Αποτέλεσμα
    1 λογαριασμοί και δικαιώματα, κωδικοί στο config_local.py, report.py με τον game_reader Δύο λογαριασμοί με λίγα δικαιώματα και προγράμματα χωρίς root
    2 SQL injection: επίθεση στο lab_unsafe.py, άμυνα στο lab_safe.py Μια ασφαλής έκδοση που αντέχει τις ίδιες επιθέσεις

    Οι δύο κύκλοι είναι οι δύο διδακτικές ώρες του μαθήματος.

    Πριν αρχίσεις, τρέξε το 01-start-state.sql (καρτέλα Import). Όλα τα αρχεία .py πρέπει να είναι στον ίδιο φάκελο, και να τρέχεις τα προγράμματα από το τερματικό μέσα σε αυτόν.

    Επιθέσεις μόνο στο δικό σου εργαστήριο

    Οι επιθέσεις του Κύκλου 2 δοκιμάζονται μόνο στο lab_unsafe.py και στη δική σου βάση. Σε οποιοδήποτε άλλο σύστημα είναι παράνομες.

    Ε. Γράψε εσύ: ο λογαριασμός game_editor (5′)¶

    Φτιάξε (στην καρτέλα SQL, ως root) τον λογαριασμό game_editor με κωδικό της επιλογής σου. Να μπορεί να διαβάζει όλους τους πίνακες της game_library και να αλλάζει (UPDATE) μόνο τον πίνακα games: ούτε INSERT, ούτε DELETE, ούτε αλλαγές σε άλλον πίνακα.

    Υπόδειξη: χρειάζονται δύο GRANT: ένα με game_library.* και ένα με game_library.games. Έλεγξε με SHOW GRANTS.

    Τι ζητάμε Απάντηση
    οι εντολές που έγραψες
    πόσες γραμμές δείχνει το SHOW GRANTS FOR 'game_editor'@'localhost';
    ποιο σφάλμα θα έδινε ένα INSERT INTO games … του game_editor;
    ποιο σφάλμα θα έδινε ένα UPDATE reviews … του game_editor;

    Κύκλος 2 — SQL injection (45′)¶

    Θεωρία (8′)¶

    Ενότητες 2.1–2.5 του μαθήματος: τι είναι το SQL injection, οι τρεις επιθέσεις, η άμυνα με παραμέτρους και τα στρώματα άμυνας.

    Α. Πρόβλεψη (3′)¶

    Πρόβλεψε το αποτέλεσμα. Μην τρέξεις τίποτα ακόμη. Δες την SQL του login_unsafe και του search_unsafe στο lab_unsafe.py.

    # Ερώτηση Πρόβλεψη
    1 Στο login_unsafe γράφεις όνομα admin'# και κωδικό x. Θα μπεις; Ως ποιος;
    2 Στο search_unsafe γράφεις zzz%' UNION SELECT username, password_hash FROM members #. Πόσες γραμμές θα επιστραφούν;
    3 Στο search_unsafe γράφεις x'; DROP TABLE members; # με λογαριασμό game_app. Θα υπάρχει ο πίνακας μετά;
    4 Το ίδιο, με λογαριασμό root. Θα υπάρχει ο πίνακας μετά;

    Δ. Γράψε εσύ: η ασφαλής find_member (5′)¶

    Πρόσθεσε στο lab_safe.py τη συνάρτηση find_member(connection, username), που επιστρέφει το μέλος με αυτό το όνομα ως (id, username, role), ή None αν δεν υπάρχει. Να είναι ασφαλής. Δοκίμασέ τη με ένα δικό σου my_check.py (με import db, import lab_safe και with db.connect() as connection:, όπως στα check_*.py των προηγούμενων μαθημάτων) και σημείωσε:

    Κλήση Αποτέλεσμα
    find_member(connection, "maria")
    find_member(connection, "zeta")
    find_member(connection, "maria' OR '1'='1")

    Υποδείξεις: ένα SELECT με WHERE username = %s· η τιμή πάει ως πλειάδα με ένα στοιχείο· μετά το execute διάβασε με fetchone(). Γιατί αρκεί fetchone εδώ (σκέψου το UNIQUE του username); ______________________________________________

    2. Ποια η σωστή άμυνα και γιατί δουλεύει; ______________________________________________
    3. Ποια δύο μέτρα περιορίζουν τη ζημιά αν παρ' όλα αυτά περάσει μια επίθεση; ______________________________________________

    Αυτοέλεγχος¶

    • □ Ξέρω να φτιάχνω λογαριασμό με CREATE USER … IDENTIFIED BY και να του δίνω δικαιώματα με GRANT.
    • □ Ξέρω να ελέγχω τα δικαιώματα με SHOW GRANTS και να τα αφαιρώ με REVOKE.
    • □ Διαβάζω τα σφάλματα #1045, #1044 και #1142.
    • □ Κρατώ τους κωδικούς έξω από τον κώδικα και ξέρω τι κάνω αν διαρρεύσει ένας.
    • □ Ξέρω τι είναι το SQL injection και μπορώ να εξηγήσω τις τρεις μορφές που είδα.
    • □ Χρησιμοποιώ παραμέτρους %s και δεν βάζω ποτέ είσοδο χρήστη μέσα στο κείμενο της SQL.
    • □ Ξέρω ότι τα λίγα δικαιώματα περιορίζουν τη ζημιά, ενώ οι παράμετροι εμποδίζουν την επίθεση.
